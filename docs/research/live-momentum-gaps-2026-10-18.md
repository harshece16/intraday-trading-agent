# Momentum book: go-live gap list (paper to real CNC on Kite)

Date 2026-10-18. Read-only review; nothing was run or edited except this file. Scope: `backend/momentum_book.py`, `momentum_alerts.py`, `kite_broker.py`, the live-order and restart parts of `trading_engine.py`, `costs.py`, `data_provider.py`, BUG_LOG.md, open GitHub issues. Ask source: `docs/research/pivot-brief-2026-10-18.md` section 4, step 1 (read from branch `docs/pivot-brief-2026-10-18`; it is not on the checked-out branch).

Severity: **B** = blocker before live, **S** = should-fix before or soon after first money, **L** = later.

## 0. Headline findings

- The paper book has **no live path at all**. Its docstring says "Paper only: nothing here places an order" (`momentum_book.py:29`). The evening job is a separate process that never touches a broker.
- The only order code is `KiteExecutor.place_order`, which hard-codes **MIS** (`kite_broker.py:52`, F&O `:133`). No CNC anywhere.
- **Whole shares at 1 L cannot hold 15 equal-weight names.** See G3.
- The paper book decides **and fills in the evening, after the fact** (the month-turn session is processed from its bhavcopy at 19:30). A live rebalance must be decided before that session's close, which the current job cannot do (G4).
- No open GitHub issue and no BUG_LOG open row is about live momentum. `gh issue list` shows 15 open issues; none is labelled `live`. Relevant open ones: #291, #263, #162, #130, #66, #260.

## 2. Can 1-2 L hold 15 whole-share positions?

Method: equal weight = capital / 15; quantity = floor(weight / price). Prices are the book's current fill prices (the 2026-10-01 fills in `backend/data/momentum_book_state.json`; the 15 held names today).

| Capital | Per name | Names that floor to 0 shares | Money deployed | Cash left idle |
|---|---|---|---|---|
| 1.0 L | 6,667 | OFSS (10,420), DIVISLAB (9,249), APARINDS (17,648) | 70.9 k (71%) | 29.1 k (29%) |
| 1.5 L | 10,000 | OFSS, APARINDS | 120.9 k (81%) | 29.1 k (19%) |
| 2.0 L | 13,333 | APARINDS (17,648) | 172.1 k (86%) | 27.9 k (14%) |

Answer: **no at 1 L (only 12 names, 29% idle); not fully at 2 L either (14 names, 14% idle)**. Four more names sit near the edge (OFSS 10.4k, DIVISLAB 9.2k, RADICO 4.2k, MCX 3.2k), so a one-share lot is 25-75% of the target weight for them. High-priced stocks are not a fluke of this month: momentum tops are often high-nominal-price names. The idle 14-29% also changes what is being tested (a part-cash book, not trial 126). Options for the prereg: raise capital to about 3-4 L; hold fewer names (for example 10); allow a named substitute rule (next-ranked affordable name); or accept an under-invested book and measure against a matched cash-drag paper copy. Each departs from trial 126 and should be written down before code.

## 4. The 5 smallest changes to allow a 500-rupee dry run (place and cancel one CNC order, outside a rebalance)

1. `kite_broker.py`: give `place_order` a `product` argument defaulting to MIS (so the intraday engine is untouched) and a `tag` argument; pass `KiteConnect.PRODUCT_CNC` and a tag like `MOMDRY` from the new caller.
2. `config.py`: add `MOMENTUM_LIVE = os.environ.get("MOMENTUM_LIVE") == "1"` (off by default), checked at the top of the new dry-run function and nowhere else yet.
3. New `momentum_live.py` (about 40 lines) with `dry_run(symbol)`: refuse unless the flag is on and `kite_session_status(probe=True)["connected"]`; read the last price with `get_quotes`; compute `qty = max(1, floor(500 / price))` and refuse if the cost is over a hard cap (for example 600); place a **LIMIT BUY at about 5% below the last price** so it cannot fill; log `order_id`.
4. In the same function: read the order back with `order_state(order_id)`, assert status is OPEN or TRIGGER PENDING, call `kite.cancel_order(variety=regular, order_id=...)`, then read again and assert CANCELLED. Append the order id, status path and quantities to `data/momentum_live_dry_run.json` (not the paper state file).
5. A one-line CLI entry (`python momentum_live.py dry-run SYMBOL`) and a test with a stand-in Kite (same style as the #155 tests) covering: flag off, token dead, order fills unexpectedly (assert it is reported, not hidden), order cancelled cleanly.

Pick a cheap, liquid, non-BE name (a few hundred rupees or less) so one share fits the budget. The dry run proves product, the order call and the cancel path; it does **not** prove a sell (G14), partial-fill carry (G6), or reconciliation (G15).
