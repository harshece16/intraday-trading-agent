# Predictive tools, part A — time-series foundation models that can be dropped into the L40 harness

**Written 2026-09-29.** Scope: any model that maps a window of bars to a forecast of the next bars, assessed as a candidate `forecast_batch(windows)` class for `backend/research/kronos_feature_ic.py` (512 five-minute OHLCV bars in, 12 closes out; scored by cross-sectional rank IC against 15/30/60-minute returns; gate in `docs/research/prereg-kronos-feature-ic.md` §8). Kronos itself is excluded as instructed. This is not a redo of the 2026-09-26 sweep, which rejected the family on published evidence; it is a tool list for the harness that now exists.

Channels used: Exa web search (`mcporter call exa.web_search_exa`), GitHub via the authenticated `gh` CLI (repo metadata, issue search, forks), the public Hugging Face model API and raw model READMEs via `curl`, and `r.jina.ai` page reads for arXiv, blogs and docs (jina was rate-blocked for `huggingface.co`, so HF pages were read raw). No logins. Companion machine-readable file: `predictive_tools_A.json` (26 candidate objects, every claim with source URLs).

## The one finding that frames everything

**No candidate has any independent out-of-sample evidence net of transaction costs on intraday stocks — Indian or otherwise.** The two finance papers that test these models (Rahimikia–Ni–Wang, arXiv 2511.18578; Noguer i Alonso–Franklin, arXiv 2606.27100) are daily, gross of costs, and null-to-negative. The only NSE, cost-aware, out-of-sample number found anywhere is negative: a model card published this summer (`sahil007123/kronos-nse-1d`) measures **pretrained Kronos-small, zero-shot, daily, 100 held-out 2026 sessions, top-80 NSE names: rank-IC −0.0116 (t −0.54), decile spread 0.046 % against a ~10 bp round trip**, while a six-line 12-1 momentum rule scores +0.0376 (t +3.51) on the same sessions. That is the right prior for L40 and for everything below. Testing more models is cheap (each is a 3-line API and runs in minutes to hours on the 3060 Ti), which is the only reason to test any of them.

## Per-candidate notes

**1. Chronos-2 (Amazon).** 120M encoder-only model, Apache-2.0, released 2025-10-30 and the most-downloaded TSFM on the Hub (22M downloads). One checkpoint does univariate, multivariate and covariate-informed forecasting with context up to 8192 and quantile output; the card claims >300 forecasts per second on an A10G and CPU support. Two bugs matter for us. PR #532 (merged 2026-09-08) shows bf16 inverse-normalisation discarded low-order bits when the level is large relative to the variation — max error 252 at level 1e5 with variation 100, which is exactly a ₹1,000–₹10,000 stock moving by ticks — so install a build after that date or run fp32. Commit 6c69155 fixed past/future covariate separation; issue #462 (Feb 2026, closed unanswered) asks whether the paper's multivariate numbers survive it; irrelevant if we pass close only. Independent evidence: 2606.27100 (five US large caps, daily returns, L = 512, gross) finds Chronos v1 DM-significant on one stock and Chronos-2 on none. No net-of-cost evidence found. **Test**, univariate close first; a second run with O/H/L/V as past covariates is a second feature and must be decided before the run because it enlarges the pre-registered family.

**2. TiRex-2 (NXAI).** The July-2026 successor to TiRex, and unlike v1 it is Apache-2.0. A recurrent xLSTM model, 38.4M active parameters in univariate mode plus 44.1M for multivariate, past and future-known covariates, strict causality over targets, quantile output and constant per-patch streaming cost. Its sLSTM CUDA kernels need compute capability ≥ 8.0, which the 3060 Ti (8.6) has. The predecessor's issue #9 ("future tokens are not masked during inference") was answered by the authors as a design property — one token per 32-step patch, N−1 NaN tokens for longer horizons — not a leak; #27 documents the 2048-step horizon cap. No finance evidence at all. **Test**, both as univariate close and with OHLCV as five variates (read the close variate's median), which makes it the cleanest multivariate comparison to Kronos.

**3. TimesFM-2.5 (Google).** 200M decoder-only univariate model (plus a 30M continuous quantile head), Apache-2.0, released 2025-09-02, context up to 16k. It is the last Apache-licensed TimesFM: 3.0 (2026-08-24, 330M, native multivariate) ships under a non-commercial, non-production licence. Leakage: issue #338 (open since 2025-11, maintainer-confirmed) — `forecast_with_covariates()` fits one ridge regression across a batch, so later items' context leaks into earlier ones when a batch is time-ordered; fix PR #393 still open. This is the covariate path only; plain `forecast()` is unaffected, and we would not use covariates. Several open NaN issues (#321, #381, #486, #507) mean a flat 512-bar window can return NaN — guard it. It is the most-tested TSFM in finance and every test is null: 2606.27100 gives it the best average rank but no DM-significant cell; 2511.18578 reports zero-shot R² of −2.80 % on daily excess returns, and (per the mental-momentum summary of that paper) a 20M TimesFM pre-trained from scratch on financial data still nets Sharpe −1.87 under 11.2/21.3 bp costs. **Test**; a null is the expected result, which is what makes a pass informative.

**4. Moirai 2.0 R-small (Salesforce).** 11M decoder-only quantile model, the only size released for 2.0 (2025-08-06), CC-BY-NC-4.0 — usable in the research harness, never in anything that trades. Issue #224 (open): accuracy drops sharply when dynamic real covariates are supplied, so pass close only. 2606.27100 ranks it joint-best on average and DM-significant on GOOG alone, gross of costs. **Test**; it costs nothing.

**5. Granite PatchTST-FM-r2 (IBM).** Released 2026-08-07 and announced 2026-09-09; 385M univariate encoder with a Conformer block, overlapping 16/8 patches, context 8192 and a 99-quantile head; dual OpenMDW/Apache-2.0. IBM's card ranks it the top permissively-licensed zero-shot model on GIFT-Eval as of 2026-08-31. No finance evidence, no known bugs. **Test** as the "best generic univariate" control; its example uses context 512, our exact window.

**6. Sundial base-128m (Tsinghua THUML).** 128M generative decoder (ICML 2025 oral), Apache-2.0, context 2880, patch 16; it returns sampled trajectories rather than quantiles, so it is the closest generic analogue to Kronos's sampling and needs the same seed and `sample_count` discipline as prereg §2. Card timing 510 ms for 2880→720 on an A100 at one sample; our 512→12 is far cheaper. Pin transformers 4.40.1 (#5). No finance evidence. **Test.**

**7. Toto 2.0 (Datadog).** Five Apache-2.0 sizes from 4M to 2.5B released April–June 2026; 313m (1.25 GB fp32) and 22m fit comfortably, 1B is borderline, 2.5B (9.1 GB fp32) does not. Native multivariate via alternating time/variate attention, nine quantiles per variate, single-pass decoding. Pre-trained on observability metrics, the furthest domain from prices of any candidate; no bugs found, no finance evidence. **Test, lower priority**, as a second multivariate OHLCV reading after TiRex-2.

**8. Granite FlowState-r1 (IBM).** 9–18M state-space model, Apache-2.0, zero-shot only, context 4096, nine quantiles, and a `scale_factor` that adapts the model's timescale to the sampling rate — record whatever value is used. Best MASE among open-code zero-shot models on GIFT-Eval as of 2026-04-28 per its card. **Test as a cheap add-on.**

**9. FinCast v1 (CIKM 2025).** The only finance-pretrained alternative to Kronos with public weights: Apache-2.0 repo (134 stars), a single `v1.pth` on the Hub dated 2025-08-26, MoE with quantile-aware loss, "any context and horizon", training-free. The paper claims zero-shot MSE 20 % below TimesFM/Chronos on its own 4.38M-point financial test set — no returns, no costs. Its parameter count ("scalable to 1B") and input format (scalar series; OHLCV not confirmed) were not verified. **Test with a change:** size the checkpoint, confirm it takes a plain price series, and apply the prereg's contamination rule — the checkpoint date precedes the 2025-09-01 selection window, so it qualifies.

**10. TimesFM-3.0 (Google).** Technically the strongest generic model (leads GIFT-Eval and fev-bench in the Forecasting Company's September table), natively multivariate with covariates and single-pass decoding, 330M. The weights are under the TimesFM Non-Commercial License v1.0, restricted to non-commercial, non-production use, while the code stays Apache-2.0. **Test with a change:** treat as research-only with results labelled non-deployable, and only if 2.5 shows any signal.

**Skips, briefly.** TiRex v1 and Chronos-Bolt are superseded within their own packages. Time-MoE weights have not moved since 2024 and it is point-only. Timer-base-84m predicts 96-step patches (wasteful for 12 bars) and is superseded by Sundial from the same lab; Timer-S1 needs ≥ 40 GB VRAM. Lag-Llama has an open scaler bug (#130: IQR = 0 divides by 1e-10) that a 512-bar window of a thin stock will trigger, and is last on every leaderboard. MOMENT's forecasting head is randomly initialised and must be trained (#17); UniTS needs prompt tuning; TOTEM trains a VQ-VAE per domain and has no licence — all three fail the zero-shot rule. TabPFN-TS regresses on time-index and calendar features, i.e. it extrapolates a curve, not bar dynamics, at seconds per window. TimeGPT is closed, metered and would ship every Kite window to a third party; 2606.27100 found nothing for it either. TimeCopilot is an LLM agent choosing among models, not a model. t0-alpha is an alpha whose stronger sibling is API-only, and its only backtest is Texas power prices where an always-short control made most of the P&L. Granite TTM-r3's paper is unreleased and its API is fixed-length.

## What I could not verify

- **The sweep's "Sharpe 6.44 gross → −3.62 at 20 bp".** The same pair is quoted by the mental-momentum summary (2026-06-06) as a global long–short evaluation of a *baseline* model in the TSFM-in-finance literature (its ref 34), alongside Rahimikia et al.'s from-scratch TimesFM-20M at −1.87 under mixed 11.2/21.3 bp costs. I fetched the 138-page 2511.18578 PDF but the text extraction did not contain those figures (they are presumably in tables or figures), so the pair is traced, not re-verified, and the sweep should keep attributing it to the literature rather than to a specific model.
- **FinCast**: checkpoint size, exact parameter count, input format and training-data cutoff (repo README and card only).
- **TiRex-2 and TiRex v1 parameter totals** are not exposed by the HF API (card figures used).
- **Per-forecast speed on an 8 GB card** for anything but Kronos: cards report A100/A10G figures (Chronos-2 >300/s on A10G, Sundial 510 ms for 2880→720 on A100, Toto ms-scale on A100); nothing was run here.
- **Granite TTM-r3** architecture (paper "to be released") and whether its top-level 1.4M safetensors file is one expert.
- **Whether any Kronos-NSE fork was evaluated intraday**: `Bhavya-Dhoot/Kronos-nse` describes a fine-tuned 5-minute regime classifier with "139 tests" but publishes no accuracy or cost number; `jvaidya10/kronos-india` publishes signals, not results.
- **GitHub issue search** was limited to five boolean operators per query; I ran two queries per repo (leak/lookahead; normalisation/scaling/NaN/future), so a bug filed under other words could be missed. Datadog/toto, thuml/Sundial and ibm-granite trackers showed nothing relevant.
- Exa's index was the only web channel; Reddit/X/YouTube channels in agent-reach were not configured and were not used.
